Assessment

Every rule is a row in a table with a SQL predicate, a severity and a remediation level. Severity comes from the rule, never decided at runtime — so the same estate always scores the same.

Target decision

The one place a model is allowed a judgement call. A proposer suggests an edition, instance class and storage; a deterministic rules engine then checks it and overrules it where they disagree — and the disagreement is recorded rather than quietly reconciled.

Measured utilization — optional

A catalogue scan cannot produce utilization percentiles — there is no history to take a percentile of. Without a feed this sizing is a capacity floor, not a load-derived recommendation. An AWS OLA / DB OLA, Migration Evaluator or monitoring export supplies it.

Remediation plan

This phase plans fixes and applies nothing. Every proposed statement carries rollback SQL or it is rejected at generation time, and passes five gates before it could reach any database. Two of those gates need infrastructure that does not exist yet — they report blocked rather than passing quietly.

Blocker gate

The last deterministic step before anything costs money or touches a target. Nothing downstream runs while a critical finding is open. A blocker can be accepted, but never anonymously — a waiver needs a named approver and a real reason, and both are recorded.

Rules & probes

Switch any check off and it will not run. Built-in checks are never edited — disabling one records the choice separately, so it can always be switched back on.

Discovery probes
A custom probe is a SELECT against the data dictionary. Its result becomes a dataset like any other. Read-only is enforced here as well as by the database account.
Assessment rules
The predicate runs against the loaded discovery data in SQLite. Return owner, object_name, object_type, detail — each row becomes a finding. Query the v_user_* views to exclude Oracle internals.
