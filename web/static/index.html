Target decision

The one place a model is allowed a judgement call. A proposer suggests an edition, instance class and storage; a deterministic rules engine then checks it and overrules it where they disagree — and the disagreement is recorded rather than quietly reconciled.

Measured utilization — optional

A catalogue scan cannot produce utilization percentiles — there is no history to take a percentile of. Without a feed this sizing is a capacity floor, not a load-derived recommendation. An AWS OLA / DB OLA, Migration Evaluator or monitoring export supplies it.

Remediation plan

This phase plans fixes and applies nothing. Every proposed statement carries rollback SQL or it is rejected at generation time, and passes five gates before it could reach any database. A gate whose infrastructure is missing reports blocked rather than passing quietly — register a rehearsal copy below and the dry run becomes real.

Fix generation
Templates + static stand-ins — not model output

Findings with exactly one correct remedy are templated, where a model would add cost and risk but no information. Where a model would answer, Bedrock InvokeModel is blocked on this account, so hand-written static output stands in. Every such answer is marked static fixture and passes the same gates a model's would.

Rehearsal database
not configured

Every fix is applied and rolled back here before production. Without it no fix can be proven safe, so none may be applied. Build it with scripts/oracle-source/06_create_rehearsal.sql. The password is held in server memory only, never written to disk.

Blocker gate

The last deterministic step before anything costs money or touches a target. Nothing downstream runs while a critical finding is open. A blocker can be accepted, but never anonymously — a waiver needs a named approver and a real reason, and both are recorded.

Migrate

      
Each step below is what the backend is about to do, in order. As it runs you see the exact
         command or SQL it executes, its output, and the evidence it ends on — passwords masked.
         Every step also says who decided it: a rule, the gate, Phase 4's advice, or you.
         The path is Data Pump, which loads tables, then rows, then indexes and constraints, then code.

Validate

      
Five levels, from it exists to it behaves. Every finding is marked
         match, expected difference with the reason it is correct, mismatch, or
         not comparable when one side cannot be read — which is never counted as a match.
         Only mismatches fail the phase. Nothing is written to either database: every statement is
         a SELECT.

Cutover

      
A readiness certificate, then a named approval, then the few target-side steps Phase 4 set
         aside. Every requirement is met, waived by a named person, not applicable
         with the reason it does not apply, or unmet — and an unmet requirement says what would
         clear it. Building the certificate changes nothing.

Rules & probes
