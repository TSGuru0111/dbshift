## Goal

Finish Phases 6, 7 and 8 **with real data moving through AWS DMS**, by putting
the Oracle source on EC2 inside the same VPC as the RDS target. Then run
Phase 8's cross-engine validation on rows that actually arrived.

This was chosen over two alternatives, deliberately:

- **Port forward from the office router** — rejected. The office public IP
  changed inside one working session (`183.82.28.170` → `14.97.44.14`, no
  reverse DNS), the laptop is `192.168.1.190` behind NAT, and it would prove
  only that *this* network can host a source, which does not transfer to a
  client's network.
- **Site-to-Site VPN** — rejected for the same dynamic-IP reason: a Customer
  Gateway needs one fixed address, so the tunnel would drop on every rotation.

The reasoning is written up in `docs/17-source-reachability.md`, addressed to a
network administrator. Do not redo that analysis.

## The one open decision

`DBMIG_TELCO` is **33 million rows / 5.7 GB**. Oracle XE caps user data at
**12 GB**, so a full-scale seed has no headroom for indexes and temp space and
may fail partway. Phase 8's level 4 checksum reads **every row on both sides**.

| Scale | Seed | DMS load | Level 4 checksum |
|---|---|---|---|
| Full 33M | 30–60 min | 45–90 min | 1–3 h |
| ~5M (CDR trimmed) | ~10 min | ~15 min | a few min |
| ~500k | ~2 min | ~2 min | seconds |

**Ask the user which, before seeding.** The previous session recommended
~500k — a checksum match proves the cross-engine canonical form works at any
volume — but the user deferred the decision until Phase 8 was actually next,
which it now is.

## Things that will bite you

- **Python does not hot-reload.** A server started before an endpoint existed
  returns `Not Found` for it forever. Both 4c and 4d now detect a 404 and print
  the restart command, but the console at `:8765` must be restarted after any
  `web/server.py` change.
- **`provision.verify` reads the password from SSM via the SDK.** The AWS CLI
  path failed with `ParameterNotFound` several times last session — a quoting
  artefact, not permissions. Use boto3, not `aws ssm get-parameter`, from bash.
- **Secrets Manager is denied** to the `DBA_permissions` role — every action,
  including `ListSecrets`. The RDS master password lives in SSM Parameter Store
  as a SecureString and that is the only place it can live today.
- **CloudFormation `DescribeStacks` is denied** on some paths but works on
  others; if a stack lookup fails, it may be permissions rather than absence.
- **Delete the stack, not just the RDS instance.** The stack owns five
  resources (security group, subnet group, S3 exchange bucket, IAM role); the
  instance alone leaves the rest orphaned.
